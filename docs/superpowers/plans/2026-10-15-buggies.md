# Two-seat neighborhood buggies implementation plan

Approved scope: four off-road buggies (orange, blue, red, green), one driver plus one passenger each, free driving and up to four competing drivers. Reuse first-person drag and joystick. Vehicles stay on the exterior road loop; household interactions remain on foot.

Architecture: deterministic vehicle simulation in the existing authenticated house network, committed in the same optimistic-lock transaction. Only the owning driver controls motion. Passenger presence is independent. Browser predicts its own motion and interpolates remote vehicles. Use existing avatar appearance for both riders. No new paid services or database migrations.

- [x] Domain tests: exclusive seats, passenger cannot steer, entry requires proximity/stopped car, exit, stale controls, bounds/collisions, ordered checkpoints and race finish.
- [x] Shared model: four vehicles, input, heartbeat expiry, two-seat occupancy, countdown, race results.
- [x] Server: authenticated global vehicle channel; validate commands and publish authoritative snapshots; preserve other world fields.
- [x] Client: controls and smoothing; fail stopped on network loss; ignore chat typing; route to parked cars; dismount on safe roadside position.
- [x] Visuals: lightweight procedural UTVs, rotating wheels, roll cage, two visible occupants; race markers.
- [x] Verification: domain/network regression tests, TypeScript, build and browser checks for two independent sessions (driver/passenger), denial of passenger driving, exit and mobile controls.
- [x] Scan changes, commit and push to authorized remote. Publish only when authorized.

Verified: 12 domain/network tests; TypeScript; full production build (596 static pages); independent browser sessions for driver/passenger and mobile-sized joystick. Browser networking uses the real exchangeNetwork handler with isolated session owners; production multi-device latency still requires a live check after deployment.
